## Why GPU was not "just pip install"

NVIDIA withdrew the prebuilt CUDA 12.2 wheels in 2025; the Jetson AI Lab
index now serves only cu126/cu128/cu129 (JetPack 6.1+). The old
`pypi.jetson-ai-lab.dev/jp6/cu122` URL in `requirements-jetson.txt` is
410 Gone. TITA is JetPack 6.0 / CUDA 12.2 and must not be upgraded — the
DDT SDK is built against 6.0. Checked DDT's GitHub: no releases, no public
images, no JetPack version stated, OTA tool updates firmware only. Nothing
public that would have saved us. Recommendation: still ask DDT's FAE (image
version, dev components, why `point_cloud` is empty) — in parallel, not
instead.

Chose **TensorRT natively** — it ships with JetPack, no wheel hunting.

## Done — TensorRT backend

Written on the laptop (cannot be tested there — no TensorRT):

- `detectors/yolox_tensorrt.py`: `YoloxTensorRTDetector` against the
  **TensorRT 8.6** API (not 10 — tutorials online are mostly 10 and do not
  run here), pycuda for buffers, own CUDA context pushed/popped per call so
  the node's worker thread can use it. Reuses `yolox_common` pre/post-
  processing byte for byte. Checks engine input size against config and
  fails with a clear message.
- `backend: tensorrt` in the factory and `detector.yaml`.
- `scripts/build_engine.sh`: `trtexec --fp16`, on the robot.
- Two tests: factory wiring (runs everywhere), ONNX-vs-TensorRT
  equivalence (runs only where an engine exists). 42 passed locally.

On the robot, what TITA was missing on top of the TensorRT runtime libs it
does ship — each found by hitting the wall:

| Missing | Symptom | Fix |
|---|---|---|
| `python3-libnvinfer`, `libnvinfer-bin` | no `import tensorrt`, no `trtexec` | apt |
| `cuda-nvcc-12-2` | pycuda cannot compile | apt |
| `cuda-profiler-api-12-2` | `cudaProfiler.h: No such file` | apt |
| `libcurand-dev-12-2` | (pre-empted) | apt |
| `pycuda` | `ModuleNotFoundError` | pip, builds from source ~5 min |

The robot **shut itself down again** mid-`apt install`, leaving dpkg
interrupted (`sudo dpkg --configure -a` fixed it). Constantin's explanation:
idle timeout when lying still with the controller off. Recorded in
`hardware/robot-access.md` — keep the controller on during long installs.

Engine built: `yolox_s_fp16.engine`, 21 MB, ~10 min. trtexec: **7.2 ms GPU
compute**, 138 qps.

| dropped | ~83 % | **4 %** |
